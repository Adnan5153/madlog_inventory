# Deploying Madlog Store on Render

This guide walks through shipping the **Laravel admin + staff panels** to
[Render](https://render.com) so a client can poke at the live application
and leave feedback. Render supports PHP 8.4 out of the box, which is
why we picked it — Vercel's PHP runtime (`vercel-php@0.7.4`) is stuck on
PHP 8.3 and can't run Laravel 13 (see "Why not Vercel" below).

The static marketing landing page (`index.html`) is **not** part of this
deployment — it lives in the repo for GitHub Pages.

## How the deployment works

`render.yaml` at the repo root declares a single web service. Render
reads it on every push and:

1. **Builds** — Composer installs PHP deps, `npm ci && npm run build`
   compiles Vite assets into `public/build/`, and `php artisan
   storage:link` creates the public storage symlink.
2. **Migrates** — `php artisan migrate --force` runs as the last build
   step (best-effort with `|| true` so a missing DB doesn't fail the
   whole deploy).
3. **Caches** — `php artisan config:cache`, `route:cache`, and
   `view:cache` run at startup so production requests hit opcached
   config and route tables instead of re-parsing files every request.
4. **Serves** — `php artisan serve` boots the dev server on the port
   Render exposes. (Render's free tier doesn't give you PHP-FPM, so
   `artisan serve` is the recommended path for small projects.)

```
Request → /admin
  ↓
Render web service
  ↓
php artisan serve (port $PORT)
  ↓
public/index.php (Laravel front controller)
  ↓
AdminDashboardController@index
```

## Why not Vercel?

We tried. The `vercel-php@0.7.4` runtime bundles PHP 8.3, but Laravel
13 + Symfony 8.1 use PHP 8.4 syntax (e.g. property hooks in
`symfony/http-foundation/Request.php`). The build succeeds but every
request dies with:

```
Parse error: syntax error, unexpected token "{"
in /var/task/user/vendor/symfony/http-foundation/Request.php on line 117
```

Until Vercel ships a runtime with PHP 8.4+, Laravel 13 can't deploy
there. Render, Railway, Laravel Forge + VPS, Heroku, and a few others
all support PHP 8.4 — Render is the simplest with a free tier.

## One-time setup in the Render dashboard

### 1. Create the Render Blueprint

- Go to <https://dashboard.render.com/blueprints> → **New Blueprint
  Instance**.
- Connect the GitHub repo. Render will read `render.yaml` and provision
  a single web service called `madlog-store`.
- It will start the first build immediately. Watch the **Logs** tab —
  the build will likely fail at `php artisan migrate --force` because
  no database is wired yet, but `|| true` keeps the deploy alive.

### 2. Add a Postgres database

You have two options:

**Option A — Render's managed Postgres (one-click)**

- Project → **New** → **PostgreSQL** → pick the **Free** plan.
- Render auto-injects `DATABASE_URL` into your web service on the next
  deploy. Done.

**Option B — Use your existing Neon database**

- If you already created a Neon Postgres from the earlier Vercel
  attempt, you can keep using it. In the web service's **Environment**
  tab, set `DATABASE_URL` manually to the Neon pooled connection
  string (`postgresql://...?sslmode=require`).
- Skip the Render-managed DB.

> The free Render Postgres tier sleeps after 15 minutes of inactivity
> and takes ~30 seconds to wake on the next request. For a client
> review demo this is fine — but if the client complains about slow
> first loads, switch to Neon (Option B) which is more reliable at
> the free tier.

### 3. Confirm environment variables

Render auto-populates from `render.yaml`. You should see:

| Variable | Source |
|---|---|
| `APP_ENV=production` | yaml |
| `APP_DEBUG=false` | yaml |
| `APP_NAME=Madlog Store` | yaml |
| `APP_URL` | auto-set to `https://madlog-store.onrender.com` |
| `APP_KEY` | auto-generated by Render, **never set this manually** |
| `DB_CONNECTION=pgsql` | yaml |
| `DATABASE_URL` | injected by Render Postgres (Option A) or set manually (Option B) |
| `SESSION_DRIVER=database` | yaml |
| `SESSION_SECURE_COOKIE=true` | yaml |
| `CACHE_STORE=database` | yaml |
| `QUEUE_CONNECTION=sync` | yaml |
| `LOG_CHANNEL=stderr` | yaml |
| `MAIL_MAILER=log` | yaml |
| `MAIL_FROM_ADDRESS=hello@madlogstore.test` | yaml |

The only thing missing from `render.yaml` is `DATABASE_URL` (set in step 2).

### 4. Run the initial migrations and seeds

The build runs `php artisan migrate --force` automatically, but the
seeds don't run. After the first successful deploy:

- Go to the web service → **Shell** tab → run:

```bash
php artisan db:seed --class=RolesAndPermissionsSeeder --force
php artisan db:seed --class=SettingsSeeder --force
```

If you have seed data for Parts / Inventory / Stock Movements, run
those too — those are the seeds that fill the dashboard charts.

## Day-to-day operations

### Triggering a redeploy

Push to `main`. Render watches the branch and rebuilds automatically.

### Watching logs

Project → **Logs** tab. `LOG_CHANNEL=stderr` means all Laravel log
output appears here.

### Rollback

Project → **Deploys** → click any previous successful deploy →
**Rollback to this deploy**. Render keeps the last 50 deploys.

### Connecting your custom domain

Project → **Settings** → **Custom Domain**. Add your domain, then
point a CNAME at `madlog-store.onrender.com`. Render auto-provisions
a Let's Encrypt TLS cert.

## Troubleshooting

### `Build failed: composer install --no-dev ...`

Common causes:

1. **`composer.lock` is out of sync with `composer.json`.** Locally run
   `composer update` and commit the regenerated `composer.lock`.
2. **Missing PHP extension.** The Render PHP image ships with the
   common extensions (pdo_pgsql, intl, mbstring, fileinfo, gd). If
   composer complains about a missing `ext-foo`, add it to
   `composer.json`'s `require` block.

### `RuntimeException: No application encryption key has been specified`

`APP_KEY` is missing. Render normally auto-generates this from the
`generateValue: true` line in `render.yaml`. If it's missing:

- Project → **Environment** → manually add `APP_KEY` set to
  `base64:<32 random bytes>`. Generate locally with:

```bash
php -r "echo 'base64:'.base64_encode(random_bytes(32));"
```

- Trigger a manual deploy (Project → **Manual Deploy** → **Deploy
  latest commit**).

### Login loops back to `/login`

Two common causes:

1. **`SESSION_DRIVER=database` but `sessions` table doesn't exist.**
   Run `php artisan migrate --force` from the Shell tab.
2. **`SESSION_SECURE_COOKIE` is `false`.** On Render the service is
   HTTPS-only, so the cookie must be marked secure. The yaml sets
   this to `true` — if you overrode it in the dashboard, restore it.

### First request takes 30+ seconds

If you're on Render's free Postgres tier, the DB spins down after 15
minutes idle. The next request waits for it to wake. Two options:

1. **Use Neon** (Option B in step 2) — Neon is more responsive at the
   free tier.
2. **Upgrade Render's Postgres** to a paid plan that doesn't sleep.

### "Application is live but no static assets load (404 on /build/...)"

`npm run build` didn't run, or ran before `composer install` did and
couldn't find `vendor/livewire/flux/dist/flux.css`. Fix:

- Project → **Shell** → run:

```bash
npm run build
php artisan storage:link
```

- Trigger a redeploy.

## Local sanity check before pushing

```bash
# Confirm composer.json is healthy
composer validate --strict

# Confirm render.yaml is valid YAML
python -c "import yaml; yaml.safe_load(open('render.yaml'))"

# Run the test suite — must be green before sharing with client
php artisan test
```
